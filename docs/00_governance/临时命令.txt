# 八、Scenario E — HITL / OCC

使用两个浏览器窗口或两个并发操作上下文。

模拟：

```text
Operator A
Operator B
```

打开同一个 Action。

A 先批准。

B 使用旧 version 再操作。

必须看到：

```text
409 CHECKPOINT_VERSION_CONFLICT
```

前端表现：

* 不是原始技术报错
* 显示刷新提示
* Refresh Latest State 可用
* 刷新后显示真实 action 状态

再验证：

```text
INVALID_ACTION_STATE
```

时：

自动获取最新状态。

并确认：

```text
Approve ≠ Execute
```

页面没有说：

* 已采购
* 已改广告
* 已发布
* 已调价

# 十九、发现 Bug 时怎么处理

本阶段原则：

如果发现：

### P0 / P1 Blocking Bug

例如：

* 跨租户泄漏
* 登录完全失败
* Operations Today 完全不可用
* SSE 完全不可用
* VIEWER 能写
* 核心页面真实数据被假数据覆盖

可以进行：

```text
Minimal Blocking Fix
```

然后重新跑相关 Scenario 和 Regression。

### P2 / P3 非阻塞

记录为：

```text
POST-V9.1 BACKLOG
```

不要边验收边大修。
